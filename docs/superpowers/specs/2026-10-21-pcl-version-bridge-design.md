# PCL 原版版本安装助手：首版设计

日期：2026-10-21

## 1. 决策与目标

做一个 Windows 本地工具，帮助仍想使用 PCL 2.99 的中国大陆玩家，把**原版 Minecraft Java Edition** 安装到他们选定的 `.minecraft` 目录，并在 PCL 中选择该版本。产品只承担版本安装，不承担账号登录、游戏启动或模组管理。

这是**技术 MVP 设计**，不是已经获得面向中国大陆公开提供下载功能的发布结论。PCL 2.99 宣布移除 MC 下载；PCL-CE 2.15.1 同期明确禁用中国大陆地区的安装功能。公开说明没有给出足以判断第三方同类工具发布边界的具体依据。因此，面向大陆的可下载安装程序及可执行下载功能的公开发布必须单独核清；换一个程序名或让 AI 帮用户安装，不改变这个问题。

用户明确的需求是：继续使用熟悉且易用的 PCL，解决新增原版版本时下载入口消失的问题。他没有要求新启动器。我们推断的首版目标用户是 Windows 上的普通 PCL 玩家，优先服务中国大陆地区；实际需求强度和愿意采用独立工具的人数尚未验证。

## 2. 方案比较

| 方案 | 用户价值 | 成本与限制 | 决定 |
| --- | --- | --- | --- |
| A. 独立原版版本安装助手，写入 PCL 使用的 `.minecraft` | 最接近“继续用 PCL，能装新版本”的诉求 | 下载实现、安全验证、PCL 兼容与大陆发布边界都要过关 | **选择，先做隔离验证** |
| B. 指导用户在 Minecraft 官方启动器安装，再让 PCL 读取同一目录 | 来源清楚，能快速验证部分流程 | 仍需另一款启动器和登录步骤，便利性较弱；PCL 能否直接使用仍需实测 | 作为可立即说明的替代路径 |
| C. 另造完整启动器或复刻 PCL 下载页 | 功能广 | 开发和维护成本高，背离用户想保留 PCL 的原因，也不解决发布边界 | 放弃 |

## 3. 首版用户流程与界面

单窗口，简体中文优先，使用 Windows 常见控件和清楚的进度反馈。

1. 首次打开时自动建议与当前 PCL 同级或 PCL 已使用的 `.minecraft`；**只显示建议路径，用户确认后才使用**。无法可靠检测时通过“选择文件夹”指定目录，不扫描或改写所有磁盘。
2. 检查目标目录结构、剩余空间和写入权限，明确展示将安装到哪里。路径若指向不正常目录、符号链接/重解析点或正在使用的版本目录，则拒绝继续并说明原因。
3. 从授权的官方来源取得原版正式版列表；默认显示最新正式版，历史正式版可搜索。快照版与加载器不在首版范围。若版本列表不可取得，展示失败原因和重试入口，不制造离线版本列表。
4. 用户选中一个版本，界面显示版本号、目标位置、预计下载量（能取得时）和“开始安装”。不要求用户配置 Java 或账号。
5. 安装期间显示“获取清单 / 下载 / 校验 / 写入 / 完成”的当前步骤、进度、失败文件及可读错误。支持取消与失败后重试。完成页说明如何回到 PCL 选择该版本；不声称已能启动，除非完成相应实测。

不在首版加入游戏启动、微软登录、Forge/Fabric、模组包、镜像源、自动更新、存档管理、文件修复或回滚。整合包和加载器也是受 PCL-CE 限制的功能，不能借首版悄悄扩展。

## 4. 技术结构

推荐 Windows 专用 `.NET 10 + WPF`，打包为自包含应用。理由是与目标平台一致、原生文件对话框与进度交互直接、运行时可随应用发布。Python + Tk/PyInstaller 更容易在当前机器起步，但终端用户分发、依赖和大型安装流程的维护负担较高；现阶段不为省一次 SDK 安装而选它。当前开发机尚未安装 `dotnet`，实施计划须先核对 SDK 获取与构建条件，不把未运行代码当成已验证。

模块边界：

- **UI**：收集目标目录和版本选择，展示状态与错误；不直接写游戏文件。
- **VersionCatalog**：从官方版本清单读取和筛选正式版；不内置或代理游戏文件。
- **InstallSource**：将版本清单解析为待下载文件及其哈希、大小、来源 URL。优先评估 MIT 许可的 CmlLib.Core，并通过适配器隔离它；采用前必须实测当前版本兼容性、来源地址、哈希行为和取消能力。若无法满足安全约束，就不接入。
- **StagingInstaller**：只在独立临时目录下载、校验；调用源适配器，不暴露对用户目录的任意写入。
- **Committer**：复核目录边界和哈希，将已校验文件合并到目标 `.minecraft`；已有文件内容不同时中止，不覆盖。最后才提交 `versions/<version-id>`，避免 PCL 看到半成品。
- **InstallJournal**：记录本次临时文件和提交步骤，供取消或中断后清理本次临时目录、解释失败原因；不删除用户原有文件。

程序**不捆绑、不转存、不在 Release 中分发** Minecraft 游戏文件。所有网络请求指向经核实的官方授权来源；禁用未审查镜像和任意 URL 输入。任何来源 URL、重定向或清单路径都须在信任边界内验证，防止目录穿越、恶意文件名和向目标目录外写入。

## 5. 文件安全和失败语义

- 默认从只读检查开始。测试使用项目自己创建的临时 `.minecraft`；不对当前真实 PCL 游戏目录运行自动写入测试。
- 安装前计算足够的临时空间和目标空间。下载只写独立 staging；每个文件按官方清单提供的哈希核验。缺少可验证哈希的关键文件不得提交。
- 目标路径按规范化后的绝对路径检查；拒绝路径穿越、目标树内的重解析点以及 `versions/<id>` 已存在的冲突。安装程序只能写 `.minecraft` 内本次版本需要的 `versions`、`libraries`、`assets` 等路径。
- 已存在且哈希相同的共享文件可复用；哈希不同则停止并让用户处理，绝不静默覆盖。存档、截图、配置、PCL 程序和其他版本都不在写入范围。
- 取消或失败时不删除旧文件；只清理本次 staging。若部分经过校验的共享文件已提交，保留并在日志中说明，重试时按哈希复用。版本目录最后提交，且不得覆盖现存目录。
- 网络、校验、磁盘不足、权限和 PCL 无法识别等错误给出明确原因、当前阶段与可执行的下一步；日志默认不含用户名、账户令牌或完整私人路径，用户可主动导出详情。

## 6. 验收与证据

技术 MVP 需逐项实测并记录环境、版本和结果：

1. 在隔离的空 `.minecraft` 中安装一个当前正式版，文件清单和内容校验通过；PCL 2.99 可以识别该版本，且不依赖 PCL 再下载本体、资源和库文件。
2. 已有其他版本、存档与配置的测试目录安装后，其预先计算的文件哈希保持不变。
3. 下载中断、哈希错误、磁盘不足、权限不足、已有同名版本和路径重解析点各有可重复的失败测试；不会出现覆盖旧文件或把不完整版本展示为安装成功。
4. 自包含包在干净 Windows 环境打开，普通用户可在不安装 Python、SDK 或 Java 的情况下完成选择目标与查看版本；实际下载验收仍受发布边界限制。
5. 最少进行 3 名目标用户的任务观察：能否在无额外解释下选对目录、安装版本并回到 PCL 找到它。未达到目标前不扩张功能。

## 7. 源码公开与成品验收（2026-10-21 更新）

用户已授权准备开源项目、选择许可证并完成授权和隐私检查。后续讨论纠正了早期判断：PCL 的下载调整及作者公告，不足以直接认定本工具违法；也不能仅凭源码开源或使用官方源保证所有发布方式均合法。因此不再把取得权利方答复或专业意见设为任何源码公开的强制前置条件。

1. 只公开有权发布的代码与资源；核对 Minecraft 条款和依赖许可，明确非官方身份，保留第三方版权与许可，不随包附带游戏内容。
2. 检查当前文件与 Git 历史中的凭据、私人路径和提交署名，必要时提供不带原历史的干净源码快照；保留原开发仓库，不擅自重写历史。
3. 公开真实的验证范围、已知限制、构建步骤、隐私处理及发布包校验值；技术预览不能表述为所有版本、所有设备均可靠。
4. 稳定成品发布前补做干净 Windows、实际启动与玩家操作验证；当前技术预览的安装和 PCL 识别测试不能代替这些验收。

本次准备的具体检查见 [release-review.md](../../release-review.md)。若出现明确的权利通知、监管要求或不同运营方式，再按具体事实核查处理，不凭假设宣称禁令或免责。

- [PCL 2.99.0.0 发布说明](https://github.com/Meloong-Git/PCL/releases/tag/2.99.0.0)：明确不再提供 MC 下载，理由为遵守相关法律法规；未列出具体条文。
- [PCL-CE 2.15.1 发布说明](https://github.com/PCL-Community/PCL-CE/releases/tag/v2.15.1)及[对应 PR](https://github.com/PCL-Community/PCL-CE/pull/3673)：明确对中国大陆地区限制安装。
- [Minecraft EULA](https://www.minecraft.net/en-us/eula)与[Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines)：允许开发符合条件的工具，但限制游戏内容分发和品牌使用；这两份材料不能单独证明大陆发行可行。
- [CmlLib.Core 仓库](https://github.com/CmlLib/CmlLib.Core)：文档宣称可列出和安装原版，仓库标注 MIT；**当前 MC 版本兼容性、实际文件校验与 PCL 互操作仍待实测**。
- “普通玩家会愿意安装第二个专用程序”“PCL 2.99 可直接使用由本工具安装的完整原版”“本方案在中国大陆可公开发布”均为待验证假设，不写成产品事实。

## 9. 后续方向：从安装助手逐步扩展到环境管理

用户在 2026-10-21 提出“像 Minecraft 版本的 Git”这一类比。它可以帮助描述查看历史版本、检查状态和恢复环境，但不能直接当作功能承诺：PCL 本身负责选择和启动已安装版本，本工具无需再实现一套启动器或 `checkout`。更贴切的定位是“原版安装助手 → 可验证的游戏环境管理工具”。

**第一优先级仍是本设计第 6 节的真实验收**，尤其是 PCL 2.99 的识别和用户能否顺利回到 PCL。只有这一闭环被证实，后续功能才有使用基础。

| 候选能力 | 要解决的问题 | 决策与进入条件 |
| --- | --- | --- |
| 已安装原版的只读完整性检查 | 不知道缺失或损坏的是哪一部分 | **下一增量首选**；复用官方哈希清单，先输出可理解的检查结果，不自动改文件；须验证大型目录的耗时和误报 |
| 定向修复缺失/损坏文件 | 发现问题后仍需重新安装 | 检查功能稳定后考虑；每次列出改动、保留冲突文件，下载与公开发布继续受第 7 节约束 |
| 游戏环境清单导出/导入 | 朋友间难以复现相同版本和模组组合 | 先访谈至少 3 名玩家并验证现有整合包工具没有满足需求；清单只记录版本、加载器与文件哈希，不附带游戏本体或未授权模组 |
| 用户配置/存档快照与恢复 | 修改模组或设置后无法回退 | 另立设计和风险评审；显示所需空间，用户主动选择范围，恢复前备份当前状态，绝不对整个 `.minecraft` 隐式做 Git 提交 |
| 运行环境自动切换、模组下载、Java 管理 | 进一步简化多环境使用 | 暂缓；范围和维护成本显著增加，且 PCL 与成熟启动器已覆盖部分需求 |

架构原则保持简单：当前 `Core` 处理标准 `.minecraft` 目录，UI 只是适配 PCL 玩家流程。后续功能通过独立的检查/清单模块加入，只有确认实际用例后才抽象多启动器适配层。不得为了“Git”比喻引入仓库、提交对象、增量存储或整目录自动回滚。
