# 原版直达：整合包安装功能设计草案

日期：2026-10-22  
状态：待用户审阅；尚未实现，不表示当前发布版已支持整合包。

## 1. 用户目标

在现有“原版直达”增加整合包功能，保持图形操作、装好后继续使用 PCL 的体验。用户不需要另装一个完整启动器，也不需要理解命令行或手动整理模组依赖。

已确认：给现有小工具增加功能，主要面向中国大陆 PCL 用户，保护已有游戏、存档及配置。

建议由本设计确定：首版接入 Modrinth，在线搜索并完整安装 Fabric 客户端整合包；同时允许导入同格式的本地 `.mrpack`。这两个入口共用同一条安装流程。本地导入仍可能需要联网下载依赖。

成功是：用户能找到一个受支持的包、选定其版本、完成安装，并在 PCL 的新隔离版本中看到正确的游戏版本、Fabric、模组和配置。“下载了 .mrpack 文件”不算安装成功；未实际启动游戏时，不声称已验证进入游戏。

## 2. 方案取舍

| 方案 | 用户收益 | 代价与限制 | 判断 |
| --- | --- | --- | --- |
| Modrinth 搜索＋Fabric 完整安装＋同格式本地导入 | 从选择到安装完成，可复用现有原版下载基础 | 首版不能安装 Forge、NeoForge、Quilt 包 | 推荐，先交付完整的可用流程 |
| 仅搜索并保存整合包文件 | 改动少 | 用户还需导入与安装；包内常只是待下载文件的索引 | 不作为首版的完成标准 |
| 同时接入所有来源和加载器 | 覆盖广 | CurseForge 接入与密钥方案、加载器安装和 Java 处理显著扩大范围 | 后续按实际包需求扩展 |

Fabric 安装能力已有 CmlLib 支持，可先复用现有依赖。具体安装 API 与继承元数据行为须在实现阶段针对当前固定版本验证，不以文档示例等同实测通过。

## 3. 首版边界

- 在线入口：Modrinth 公开整合包搜索，关键词、MC 版本筛选、分页、项目简介、作者、来源链接及包版本选择。界面持续提示“首版支持 Fabric 整合包”。
- 版本列表只提供 Fabric 包版本；默认选包的最新正式发布版本，测试版须显式勾选才显示。包的发布类型与 MC 的正式版类型分别校验。
- 安装前下载并检查索引，最终以包内声明为准，不能只信搜索标签。仅接受 Minecraft 正式版＋一个 Fabric 加载器的组合；不擅自替换成最新版 MC 或加载器。
- 本地导入仅支持 `.mrpack`。未知格式、未知必需依赖、其他加载器在写入目标游戏目录前明确拒绝。
- 首版包文件下载来源限定 Modrinth CDN。索引中的必要文件若没有允许的地址，安装前报明原因；不能跳过后显示成功。此限制会排除部分使用外部文件源的合法包，UI 和 README 必须说明。
- 不做账号登录、游戏启动、服务器包、模组商店、整合包更新合并、卸载或已有实例覆盖。Java 选择和游戏启动仍由 PCL 负责。

## 4. 页面与操作流程

沿用当前浅色、蓝色重点按钮的风格。顶部保留“原版直达”，内容区增加“原版 / 整合包”两个页签，沿用已有游戏目录选择与确认操作。

1. 进入“整合包”，主动搜索，或点击“导入 .mrpack”。
2. 在线结果展示名称、作者、简短描述、游戏版本及来源；点击后选择包版本。搜索失败允许重试，不阻塞原版功能。
3. 检查包索引，展示 Minecraft / Fabric 版本、文件数量、预计下载量和新实例名称。实例名称默认由包名与版本生成，用户可修改；不能指向已有版本。
4. 若包含客户端可选文件，列出可勾选项，默认全选并说明可取消；客户端不支持的文件不安装。缺省环境按规范处理。
5. 点击“安装整合包”，依次展示检查、原版与加载器、模组下载、校验、写入进度，可取消。检查阶段不伪造确定百分比。
6. 成功后显示“已安装，请回到 PCL 选择此版本”，附实例名称、打开安装目录入口。Java 或内存配置问题给出 PCL 操作提示，不表示游戏已启动成功。

任一安装运行时禁止开始第二个安装或修改已确认目录；可继续取消。切换项目、修改筛选或重新搜索后，旧请求结果不能覆盖新选择。

## 5. 模块与数据流

沿用 WPF / .NET 10 / CmlLib.Core，暂不增加第三方整合包执行器。

- `ModrinthCatalog`：有大小上限的 API 请求、分页与响应校验，返回项目和版本数据；与原版版本目录独立。
- `MrpackReader`：读取 ZIP 索引，验证格式、客户端环境、依赖、路径与展开上限；输出安装计划，不写游戏目录。
- `ModpackDownloader`：只下载计划选定的文件，限制来源、重定向、体积和并发，校验长度及索引哈希。
- `FabricInstallSource`：在临时目录准备固定 MC 与 Fabric 版本，核查继承关系与所需库。不通过修改原版官方来源限制来兼容模组下载。
- `ModpackInstallCoordinator`：合并下载与 overrides，形成完整的暂存清单，调用安全提交逻辑；产出新实例和来源记录。
- `ModpackViewModel`：搜索、选择、预检、可选文件和任务状态；原版界面保留自己的选择状态，共享单任务安装控制。

数据流：搜索 / 本地文件 → 索引验证 → 用户确认新实例与选项 → 临时目录准备全部依赖 → 校验 → 提交新实例 → 引导回 PCL。

不重构无关模块。扩展提交器时必须保留现有路径、链接、冲突与共享文件哈希检查。

## 6. 安装布局与文件保护

- 每个包新建 `.minecraft/versions/<实例ID>/`；模组、配置与包附带内容位于这个新实例中，不写入根目录的 `mods`、`config` 或 `saves`。
- 游戏资源与库可使用根目录 `assets`、`libraries`；只补充缺失文件。已有同名内容哈希不符即停止，不覆盖。
- 保留加载器标准的原版继承关系，不自行改写合并游戏启动参数。若原版父版本缺失，在全部下载校验后先提交完整的原版父版本，再提交整合包实例；已有父版本须验证为预期内容，否则报冲突。安装预览说明可能补充一个原版父版本。父版本提交后若取消或包提交失败，这个完整父版本可以保留，不能留下半成品整合包。
- 包附带内容按 `overrides`、`client-overrides` 的层次顺序合并；忽略服务端覆盖层。层内大小写冲突、重复或文件/目录冲突拒绝；规范允许的跨层覆盖只发生在临时目录。
- 包文件不能覆盖生成的启动 JSON、版本 JAR、`PCL/` 配置、来源记录或共享依赖目录。保留目录出现包内容时预检报错，不静默丢弃。
- 仅给新实例写入程序生成的 PCL 版本隔离设置。已查到 PCL 上游安装代码使用 `VersionArgumentIndie:1` 和 `VersionArgumentIndieV2:True`；用户当前 PCL 2.99.0.0 的实际行为仍需隔离验证，不能仅据上游 main 声称兼容。
- 完成全部下载、合并和校验后，最后移动新实例目录，使不完整实例不出现在 PCL。失败可能留下已验证的共享缓存和已完整提交的原版父版本，但不能留下可选择的半成品实例。
- 同名目录存在或提交期间被其他程序创建：拒绝覆盖。取消、网络失败及空间不足：清理本任务暂存文件，保留用户现有内容。

## 7. 网络、归档与隐私约束

Modrinth API 使用独立客户端和可识别的 User-Agent；不需要用户账号或内置私钥。尊重服务返回的限流与重试信息，不自动循环搜索。正文大小、版本数量与超时均有上限。

游戏官方源、Fabric 元数据与 Maven、Modrinth API、Modrinth CDN 分别设定用途与主机规则。只允许 HTTPS，拒绝凭据 URL、非标准端口及不允许的重定向目标；不接受包随意新增下载主机。

索引须包含合法 SHA-1 与 SHA-512；下载同时核对两者及长度。来自 API 的包文件也核对其公布的大小与哈希。哈希验证表示内容与清单一致，不表示模组代码经过安全审计。

ZIP 拒绝路径穿越、绝对路径、Windows 保留名称、重解析点/链接、大小写碰撞和加密条目。初始保护上限：包文件 512 MiB、索引 8 MiB、条目 20,000 个、单文件 1 GiB、实际展开总量 4 GiB、模组下载总量 8 GiB；既检查声明值，也按实际流式字节执行。超限给出明确错误，不静默截断。

不执行包内脚本、安装程序或启动命令；不继承包附带的启动器账号、认证及外部命令配置。模组 JAR 由 PCL 启动游戏时加载，界面应展示作者与来源，便于用户选择可信包。

不增加遥测。搜索词与下载请求会发送至来源服务；更新隐私声明说明请求目的。日志不包含本机完整路径、账号和密钥。来源记录保存项目/包版本 ID、MC/Fabric 版本及哈希，供故障反馈，不保存敏感信息。

## 8. 验收标准

1. 当前原版功能及现有 43 项测试继续通过；不改变原版版本列表的筛选语义。
2. 真实 API 搜索、分页、包版本选择可用；空结果、限流、无网络和取消都显示可理解的状态。
3. 格式、可选文件、覆盖层、坏哈希、恶意路径、链接、归档超限、未知加载器、禁用来源均有自动化测试。
4. 取消、磁盘不足、已有版本冲突及提交竞争有测试；事先放入的存档、配置和既有版本在失败测试前后哈希相同。
5. 使用固定项目与版本 ID 的真实轻量 Fabric 包，在隔离目录完成一次完整安装；另验证同一文件的本地导入。记录最终依赖清单与哈希，不在仓库分发包内容。
6. 在隔离的 PCL 2.99.0.0 环境检查新实例、MC/Fabric 识别及隔离设置。未验证的 PCL 版本和实际进入游戏情况分别标注，不泛化。
7. 打包新预览版本、补齐来源/限制/依赖/隐私文档后再提供给用户。不把未完成的功能写成当前发布版能力。
