# Friends and pinned modpack invitations implementation plan

> **For agentic workers:** Use TDD and isolated file ownership for independent backend/client/UI work, followed by integration and one fresh security/code review. Steps are tracked below.

**Goal:** A working optional friends feature with a separately runnable, persistent local service and honest unconfigured/public-service states.

**Architecture:** Existing .NET 10 WPF app and Core share transport DTOs. An ASP.NET Core Identity + EF SQLite service owns authoritative relationships and account sessions. The client never trusts peer-provided downloads and feeds source-verified exact releases into existing preflight/install guards.

**Tech Stack:** .NET 10, WPF, ASP.NET Core Identity/EF Core SQLite 10.0.0, Windows DPAPI. No new hosted account or paid provider.

**Spec:** docs/superpowers/specs/2026-10-23-friends-design.md (user said “run” after the proposal).

## Global constraints

- Installer remains login-free; no fake friends, presence, delivery/read claims or automatic installation.
- Public origins HTTPS only; literal loopback HTTP permitted only with explicit development configuration. No auth redirects/cross-origin token leakage.
- Page size20, request/invitation lifetime7days, repeat cooldown24hours, friend limit200, request10/day/pending20, invite30/day, lookup30/minute.
- Independent account identity, no Microsoft/PCL credentials. Public DTOs never expose emails.
- Existing modified/untracked publishing files are preserved; commits stage explicit paths only. No original private-history push.
- Public production deployment and two-physical-machine tests require a real endpoint/email provider not present here; implement and validate local service, document this remaining external gate.

## Review focus

1. Auth revoked/expired/forged credentials must fail protected and refresh requests.
2. Relationship/block changes racing invites cannot permit an unrelated actor or revive a friendship.
3. Out-of-order/failed UI requests and logout cannot restore old account state.
4. Exact version and SHA512, missing/unsupported source metadata never silently select another file/version.
5. No configured service/network failure must leave existing installation usable and cannot show successful friend mutations.

## Execution decisions

- User “run” authorizes execution of the design; use independent backend/client/UI agents on disjoint directories to save elapsed time. Root handles shared contracts, pack integration and final verification.
- No public service is invented. Local development inbox files replace outgoing email only in explicit Development mode; UI/docs identify them as such.
